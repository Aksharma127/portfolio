Projects / Headless_BAI

Headless_BAI

A web page that reorders its own sections based on how visitors behave, using behavioral telemetry, offline K-Means clustering and an LLM layout step.

Source on GitHub ↗All projects

What it does

Most sites show every visitor the same layout. Headless_BAI watches how a session behaves (where the pointer goes, how fast, how often it clicks), assigns the session to a behavioral cohort, and reorders the page sections for that cohort. The reorder is animated so the page never jumps.

It was my B.Tech capstone. The public repo holds the telemetry, ingestion, clustering and layout pipeline. The custom Chromium build and the LLM layout step are documented in the capstone report.

How data moves through it

If live ML is unavailable, the API serves the last computed layout from cache. Every response carries a source field: cache, live_ml or cache_fallback.

Design decisions

  1. Filter bots before clustering

    Synthetic or scripted sessions would pull the centroids toward nonsense cohorts. A detector drops sessions that cross spatial variance (θ = 10.0), temporal variance (θ = 100.0) or click frequency (θ = 10 Hz) thresholds before anything reaches K-Means.

  2. Weight recent behavior more

    Preferences are updated with exponential decay (α = 0.2), so a visitor's last few interactions count more than what they did at the start of the session.

  3. Keep clustering offline

    K-Means runs on a schedule, not on the request path. The request path only reads the cached layout, which keeps the telemetry script under 1 ms of main-thread time.

  4. Read layout geometry from the browser itself

    A custom-compiled Chromium binary exposes native DOM bounding boxes without extra rendering work. Llama-3-8B on Groq then produces a deterministic layout as JSON at temperature 0.1.

Testing

30 pytest tests cover spatial (6), temporal (4) and frequency (5) features, bot detection (5), the interaction schema (6) and ingest payloads (4). GitHub Actions runs them against a Redis 7 service container on every push. The stack starts locally with Docker Compose.
